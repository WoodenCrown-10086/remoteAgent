# Code Review（代码审查）

## 审查维度（逐文件逐行）
1. **正确性**：逻辑边界、并发、空值、类型断言、异常路径
2. **安全**：注入（SQL/命令/HTML）、路径穿越、密钥泄露、越权、反序列化
3. **行为变化**：API 签名变更的调用方、默认值变化、错误处理吞异常
4. **测试**：新增逻辑是否有测试覆盖；缺失的边界用例
5. **隐藏问题**：竞态、内存泄漏（未清理的 listener/timer）、死代码、硬编码

## 输出格式
- 按文件分组，每条：`文件:行号 - 严重度(阻断/建议) - 问题描述 - 修复建议`
- 结论段：是否可合并、必须修复项清单

## 原则
- 只评事实，不评风格偏好（除非项目规范明确）
- 对每条问题给出可执行的修复方向，不空泛批评
