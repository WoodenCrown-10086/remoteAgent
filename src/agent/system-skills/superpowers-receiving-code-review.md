# Receiving Code Review（接收代码审查）

## 流程
1. 逐条阅读审查意见，不跳过、不抵触
2. 每条评估：
   - 认同 → 修复（说明修复方式）
   - 有争议 → 解释原设计理由，或提出折中，不硬顶
3. 修复后复跑验证（构建/测试）
4. 回应总结：已修哪些、为何保留哪些

## 原则
- 审查意见是找 bug 的免费劳动力，不是批评
- 即使是风格建议也先评估（项目规范优先）
- 不"机械照改"也不"全盘拒绝"，每条独立判断
