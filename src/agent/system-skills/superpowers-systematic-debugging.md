# Systematic Debugging（系统化排错）

## 流程
1. **复现**：拿到可复现的最小步骤/输入（不要"偶尔出现"）
2. **读证据**：错误栈、日志、返回值——定位到具体文件行，不猜
3. **提假设**：列出 2-3 个可能根因，按可能性排序
4. **最小验证**：用最小改动/最小输入验证第一个假设（加日志、隔离函数、构造最小用例）
5. **确认后修复**：改根因，不改表象
6. **回归验证**：修完跑原场景 + 相关测试

## 反模式
- 不"乱改试试"（每次改之前要有假设）
- 不靠加一堆日志猜（先看已有日志/错误）
- 不修"症状"（比如只加个 try-catch 吞异常）

## 输出
- 根因（含证据链）→ 修复 → 验证，三要素齐全
