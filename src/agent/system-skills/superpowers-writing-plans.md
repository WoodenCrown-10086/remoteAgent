# Writing Plans（写计划）

## 拆解原则
- 每个步骤：单一、可执行、有明确完成标准（"改完 X 文件并跑通 Y"）
- 步骤顺序按依赖：数据 → 逻辑 → 展示 → 联调
- 每步尽量小（能在一次迭代内完成并验证）

## 计划格式
1. 目标与验收标准（怎么算完成）
2. 步骤列表，每步含：做什么、改哪些文件、怎么验证
3. 风险点与回退方案（哪步可能卡住、怎么绕）

## 执行中的调整
- 计划是地图不是枷锁：发现新信息及时更新计划，但每一步仍要可验证
- 步骤被卡住 → 拆更小或换路径，不要硬啃
