# PRD → Coding（需求转代码）

## 流程
1. 解析 PRD：功能点、用户角色、验收标准、边界条件
2. 拆解为技术任务：数据模型、API、页面、状态管理
3. 不确定的需求先列出假设，标注需确认项，不要擅自发明
4. 按依赖顺序实现：数据层 → API → UI → 联调
5. 每条验收标准对应一个可验证的测试/检查点

## 输出格式
每个任务实现后输出：
- 改动文件清单
- 对应 PRD 的哪条需求
- 验证方式（命令/测试/手工步骤）

## 注意事项
- 不实现 PRD 没写的功能（不"顺便加"）
- 与 PRD 冲突时以 PRD 为准，但指出矛盾点
- 多轮实现：先最小可用（MVP），再迭代补全
