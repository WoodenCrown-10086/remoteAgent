# TDD（测试驱动开发）

## 循环（红-绿-重构）
1. **红**：先写一个失败的测试（描述期望行为）
2. **绿**：写最小实现让测试通过（不做多余的事）
3. **重构**：在不改行为的前提下清理实现（消除重复、命名、结构）

## 规则
- 测试先行：没有测试的"先实现"违反 TDD
- 每步测试只测一个行为
- 测试失败必须"真的失败"（不是编译错误或误断言）
- 小步前进：一次只加一个测试，不批量

## 适用场景
- 有明确行为可断言的逻辑（纯函数、状态机、解析器、计算）
- 重构前的安全网
- 不适用：一次性脚本、纯视觉/交互原型（这类用验证代替）
